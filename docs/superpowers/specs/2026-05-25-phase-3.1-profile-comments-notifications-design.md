# Phase 3.1: ProfilePage + 评论 + 通知 — 设计文档

## 概述

Phase 3 拆分为三个子阶段。3.1 聚焦个人设置、任务评论和通知系统，同时建立 SSE 实时事件基础设施供后续阶段复用。

**技术决策摘要：**

- SSE（非 WebSocket）做实时推送，单端点 `GET /api/v1/events/stream`
- 评论一级嵌套（与 Jira 一致），@tiptap/react 富文本编辑器
- 通知同步写入 + SSE 推送，Bell 下拉面板展示
- ProfilePage 纯文本字段，头像上传延后到 3.2

---

## 1. SSE 实时事件系统

### 端点

```
GET /api/v1/events/stream
认证: Bearer Token
超时: 5 分钟（SseEmitter timeout）
```

### 后端架构

```
SseEmitterRegistry（@Component，ConcurrentHashMap<Long userId, SseEmitter>）
  ├── register(userId)    → 创建 SseEmitter(5min)，存入 registry
  ├── unregister(userId)  → 移除并 complete
  └── send(userId, event) → 查 registry，SseEmitter.send()

EventsController
  GET /api/v1/events/stream
    → registry.register(userId)
    → onComplete/onTimeout → registry.unregister(userId)
```

与 AI Chat 的区别：AI Chat 用 `Flux<String>` 做一次性请求-流式响应，SseEmitter 做持久连接。

### 事件格式

```
event: notification
data: {"type":"MENTIONED","title":"张三 在 PROJ-42 中 @ 了你","referenceType":"comment","referenceId":99,"createdAt":"..."}

event: comment_added
data: {"taskId":42,"commentId":99,"author":"张三","preview":"这个优先级需要..."}

event: task_assigned
data: {"taskId":42,"assignee":"张三","title":"修复登录页面样式"}
```

### 前端

- `useRealtimeEvents` hook，基于 `fetch + ReadableStream`（复用 AI Chat 模式）
- 在 `AppLayout` 层挂载，全局共享一个连接
- 断开自动重连（5 秒间隔，指数退避）
- 收到事件 → 分发到对应 store/回调

## 3. 评论系统

### API

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/tasks/{id}/comments` | 创建评论，body: `{ content, parentId? }` |
| GET | `/api/v1/tasks/{id}/comments` | 分页列表，`?page=&size=` |
| PUT | `/api/v1/comments/{id}` | 编辑自己的评论 |
| DELETE | `/api/v1/comments/{id}` | 删除自己的评论 |

### 数据模型

已有 `task_comments` 表 (V2)：
```
id | task_id | parent_id (可空) | user_id | content (文本/Markdown) | created_at | updated_at
```

### 一级嵌套策略

- `parent_id IS NULL` 的为顶层评论
- `parent_id IS NOT NULL` 的为回复，直接挂在顶层评论下
- 不允许"回复的回复"（后端校验：parent_id 指向的评论自身的 parent_id 必须为空，否则拒绝）
- 查询：先查顶层评论（分页），再批量查它们的回复（IN parent_ids）
- 编辑评论不重新触发 @ 提及通知

### @ 提及机制

```
用户输入 "@" → tiptap 扩展触发
  → 调 GET /api/v1/users/suggestions?q=...
  → 弹出下拉列表，用户选择
  → 插入为 Markdown: [@张三](/users/3)

后端保存评论后:
  → 正则提取所有 [@xxx](/users/\d+) 中的 userId
  → 去重
  → 写入 notifications 表（type=MENTIONED）
  → SSE 推送给被提及用户
```

### 编辑器

- @tiptap/react，StarterKit + 自定义 @ 提及扩展
- 输出 Markdown 存储到数据库
- 工具栏：加粗、斜体、列表、代码块、@ 提及

### 前端展示

- TaskDetailDrawer 改为 Tabs 结构：Tab 1 "详情"、Tab 2 "评论 (N)"
- 评论区：评论卡片 + 回复按钮 + 一级缩进显示回复
- 每条评论显示：头像、用户名、时间、Markdown 渲染内容
- `[@用户名](/users/3)` 渲染为可点击的用户链接

## 4. 通知系统

### API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/notifications` | 分页列表，`?page=&size=`，未读优先 |
| GET | `/api/v1/notifications/unread-count` | 返回 `{ count: 3 }` |
| PATCH | `/api/v1/notifications/{id}/read` | 标记单条已读 |
| PATCH | `/api/v1/notifications/read-all` | 全部已读 |

### 3.1 通知类型

| 类型 | 触发时机 | 触发位置 |
|------|----------|----------|
| `TASK_ASSIGNED` | 任务的 assigneeId 变更（且新负责人不是你） | TaskService.updateTask() 中检测旧值 ≠ 新值 |
| `COMMENT_ADDED` | 你的任务有新评论（且评论者不是你自己） | CommentService.create() |
| `MENTIONED` | 评论中 @ 了你 | CommentService.create() 解析后 |

### 触发流程（同步）

```
业务操作（CommentService / TaskService）
  → 构建 Notification 对象
  → notificationMapper.insert(notification)
  → sseEmitterRegistry.send(targetUserId, notificationEvent)
```

### 已有数据表

```
notifications: id | user_id | type | title | body | reference_type | reference_id | is_read | created_at
```

- `reference_type/reference_id` 用于点击跳转（如 `reference_type=task, reference_id=42`）

### 前端

**Bell 图标（Header 已有占位符）：**
- 挂载时调 `GET /notifications/unread-count` → Badge 显示
- SSE 收到 `notification` 事件 → unreadCount +1
- 点击单条通知 → 标记已读 + 跳转任务详情

**Bell 下拉面板：**
- 最近 10 条通知
- 每条：类型图标 + 标题 + 时间（如"3 分钟前"）
- 未读项左侧蓝点标识
- 底部"全部已读"按钮

**数据获取：**
- `useNotificationStore`（Zustand）：unreadCount、recentList
- SSE 事件实时增量更新，页面初始加载调 GET 获取已有通知
